# 실행과 복구 검증 기록

## 0.5.1 답변 상한 잘림 반려

hal-camera에서 0.5.0으로 `docs-sync`를 `force=true`로 실행한 실측 기록입니다. 2026-09-19, self-hosted Windows runner, Ollama `qwen3.5:4b`, 컨텍스트 49,152.

- 구조 스캔: 관점 3개, 요소 54개를 요소 단위로 스캔해 필드 44개를 수정했고 반려 0회, 약 6분. 요소 단위 스캔·`scan.json`·`omm validate`가 실제 모델로 동작함을 확인했습니다.
- 원고: `architecture.md/overview`는 근거 5조각 요약 뒤 집필에 통과했습니다. `architecture.md/module-roles`는 "필수 심볼" 사유로 3회 반려되어 전체 실패. 재시도 두 번의 출력이 정확히 1,000토큰이었으므로 답변 스키마 `maxLength: 2500`이 답변을 끊은 것으로 판단했습니다.
- 0.5.1 조치 후 모의 서버 검사 129개 중 123개 통과. 실제 Qwen 재실행은 hal-camera가 0.5.1로 올린 뒤 기록합니다.

## 0.5.0 요소 단위 스캔·구조화 집필·프로젝트 검사 명령

hal-camera에서 가져온 요소 단위 스캔, 구조화 집필 계약, 스트리밍 전송과 새 명령 `coverage`·`site`·`check`를 검사했습니다. 2026-09-17, Windows, Node 24.18.0.

- `npm test` 128개 중 122개 통과, 6개는 실제 Qwen·Hermes가 필요해 건너뛰었습니다. `test/sync.test.mjs`(65개)는 스트리밍 응답 재조립과 시간 제한, 요소 스캔 캐시와 `--force`, 형제 요소 격리, 근거 분할 요약과 길이 초과 재시도, 실패 주입 13종에서 원본 보존, 반영 복구·잠금을 다룹니다. `test/rejection.test.mjs`(8개)는 0.4.0의 반려 검사를 요소 단위 스캔과 조립 계약으로 옮긴 것이고, `test/site.test.mjs`(9개)는 사이트 빌더의 결정론·매니페스트 정리·링크 검사입니다. CI는 ubuntu와 windows에서 통과했습니다.
- hal-camera 작업본(관점 3개, 요소 57개, 원고 5건)을 이 엔진으로 `check --build` 6단계 통과, `sync --dry-run`이 파일을 바꾸지 않음, 요소 57개의 스캔 입력이 모두 60,000자 이하임을 확인했습니다. 집필 규칙 원문이 hal-camera 사본과 README 한 줄 달라 원고 5건이 재검토 대상이 되었고, 본문 변경 없이 다시 승인했습니다.
- 확인하지 못한 것: 이 버전으로 실제 Qwen `sync`를 끝까지 실행하는 것, Hermes 경로에서의 요소 단위 스캔, Jira·Confluence 실접속. 이전 Ollama 검사 두 개는 `fetch`를 바꿔치기하고 있었는데 스트리밍 전송은 `node:http`를 쓰므로 실제 로컬 Ollama에 요청이 가고 있었습니다. 루프백 서버로 바꿨습니다.

## 0.4.0 관점별 다이어그램 종류 검사

바인딩의 `diagram_type`, 종류별 검사기, 종류에 맞춘 스캔 프롬프트와 반려 안내, 종류 불일치 시 `generate` 실패, 종류 변경 시 재검토 전환을 검사했습니다. 69개 중 66개가 통과했고 실행 조건이 없는 3개는 건너뛰었습니다. 예제에 class·sequence·state 관점을 추가하고 미리보기에서 Mermaid 11이 네 종류를 모두 렌더링하는 것을 확인했습니다. 정식 설치한 Hermes 0.21.3과 로컬 Ollama `qwen3.5:4b`로 예제 `sync --force`를 7회 실행하여 문법 예를 넣기 전 4회 중 0회, 넣은 뒤 3회 중 2회 성공했고, 실패한 실행은 모두 원본을 바꾸지 않았습니다. 4B 모델은 sequence 그림에 코드 문장을 넣는 일이 잦으므로 사람의 대조가 필요합니다. 27B 모델과 사내 서비스 실접속은 확인하지 않았습니다. 수치와 재현 조건은 [0.4.0 변경 기록](releases.md)에 정리합니다.

## 0.3.3 원고·구조 응답 반려 검사

집필 프롬프트의 문체 예시, 원고 검사기와 반려 재요청, 조사 띄어쓰기 정리, 구조 스캔 검증 실패 시 복원과 재요청, 리뷰에서 나온 YAML 오류·요소 불일치·OMM 시간 초과·프롬프트 한도 처리를 검사했습니다. 64개 중 61개가 통과했고 실행 조건이 없는 3개는 건너뛰었습니다. 정식 설치한 Hermes 0.21.3과 로컬 Ollama `qwen3.5:4b`로 예제 `sync --force`를 반복 실행하여 수정 전 8회 중 3회 실패하던 동기화가 수정 후 5회 중 4회, 리뷰 반영 후 3회 중 3회 성공했고, 실패한 1회는 원본을 바꾸지 않은 것을 확인했습니다. 통과한 원고의 형식 위반은 없었으나 4B 모델의 사실 오류는 남아 있으므로 사람의 대조가 필요합니다. 27B 모델과 사내 서비스 실접속은 확인하지 않았습니다. 수치와 재현 조건은 [0.3.3 변경 기록](releases.md)에 정리합니다.

## 0.3.2 Hermes 추론 비활성화 검사

Hermes 일회성 프로필의 추론 비활성화, 세션 제목 요청 제거, stdout 안내 문구 해석, 재시도를 검사했습니다. 실제 Hermes 0.21.1과 로컬 모의 API를 연결한 검사를 포함해 47개 중 45개가 통과했고, 실제 Qwen이 필요한 2개는 건너뛰었습니다. 로컬 Ollama의 `qwen3.5:4b`로 수정 전후를 비교하여 추론이 꺼지고 큰 프롬프트가 완료되는 것을 확인했으며, 27B 모델과 사내 서비스 실접속은 확인하지 않았습니다. 수치와 재현 조건은 [0.3.2 변경 기록](releases.md)에 정리합니다.

## 0.3.0 읽기 중심 디자인 검사

`reading` 프리셋을 기본 예제에 적용했습니다. 자동 검사 30개 중 28개가 통과했으며 실제 Qwen 호출 2개는 이번 디자인 변경에서 생략했습니다. reading과 architecture 모두 정상 동기화, 근거 집계, 코드 변경 후 재검토 상태를 확인했습니다. 디자인 작업은 검토 승인을 변경하지 않습니다.

## 0.1.0 실행 검사

**공용 실행기 0.1.0의 로컬 검사 28개가 모두 통과했습니다.** 2026-09-11에 Windows, Node 24.18.0, Ollama 0.33.3, Qwen `qwen3.5:4b`, OMM 0.2.0으로 확인했습니다.

```powershell
$env:DOCGEN_REAL_QWEN = '1'
node --test --test-concurrency=1 test/*.test.mjs
```

| 범위 | 확인 결과 |
| --- | --- |
| 로컬 Qwen과 OMM | 관측 시간이 10000ms에서 12000ms로 바뀌자 부모·자식 구조 설명과 생성 페이지가 갱신됐습니다. |
| 별도 C++ 코드 경로 | 문서 프로젝트 밖의 C++ 파일을 읽어 문서를 갱신했으며 원본 코드는 유지됐습니다. |
| 모델 실패 | 시간 초과·HTTP 오류·잘못된 JSON·출력 잘림에서 원본 바이트가 유지됐습니다. |
| 생성 실패 | 허용하지 않은 인용·OMM 오류·두 번째 원고 실패·마커 오류·CSS 누락에서 부분 결과를 반영하지 않았습니다. |
| 파일 반영과 복구 | 반영 도중 실패를 되돌렸으며, 중단 기록 복구와 후속 사용자 편집 보호를 확인했습니다. |
| 변경 커밋 | 임시 Git 저장소에서 검토 기준 커밋 이후의 변경, CSWPR ID, 한글 파일 경로, 작업본 변경 거부를 확인했습니다. |
| Jira·Confluence | 모의 응답으로 필드 분리·출처·개정 정보·첨부 링크·선택 기능과 필수 연동 실패를 확인했습니다. |
| Hermes | 모의 실행 파일로 Qwen 프로필과 CLI 인수를 검사하고, 에이전트가 파일을 바꾸면 반영을 거부하는 것을 확인했습니다. |
| 시각적 형식 | Slack·plain·custom 전환과 색상 입력 검사를 통과했습니다. |

현재 HALCamera 앱에서는 공용 엔진으로 실제 `sync`를 실행했습니다. 검토 대상이 최신이어서 모델을 호출하지 않고 0개 파일 변경으로 완료했습니다. 기존 앱 검사 27개도 통과했습니다. 앱의 실제 Qwen 검사는 별도로 이미 실행했으며, 이번 앱 회귀 실행에서는 해당 1개를 생략했습니다.

Slack 디자인을 적용한 소개·빠른 시작·아키텍처·디버깅 페이지를 Chrome의 1360px와 390px 화면에서 확인했습니다. 가로 화면 넘침이 없었으며 그림 확대·닫기가 동작했습니다. README의 Mermaid 그림 4개도 렌더링했습니다.

**사내 연동 검증은 별도로 남아 있습니다.** 실제 Hermes, Jira·Confluence 인증과 필드, Gerrit 미러링 완료 신호, 정기 작업 등록은 사내 환경에서 확인해야 합니다. 첨부 이미지는 현재 링크만 수집합니다. 큰 코드 범위는 입력 한도 안에서 계약이 유지되도록 모듈별로 나누어야 합니다.
