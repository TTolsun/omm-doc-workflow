# 17:00 미러링과 연결하기

**기존 미러링의 성공 후 단계에서 `docflow sync`를 호출하세요.** 17:00은 기존 Gerrit → GitHub 미러링의 시작 시각이며, 문서 작업은 미러링이 끝난 코드를 사용합니다. 이 시스템은 별도의 cron을 자동 등록하지 않습니다.

미러 작업이 로컬 스크립트라면 성공한 명령 다음에 아래 호출을 추가합니다. 미러 작업이 GitHub Actions라면 같은 workflow의 성공 후 job이나 완료 이벤트를 사용합니다. 실제 workflow 이름과 저장소는 셋업 시 지정합니다.

```bash
# 기존 미러 작업이 성공한 뒤 실행합니다.
node /opt/omm-doc-workflow/bin/docflow.mjs sync \
  --project /work/camera-hal-docs \
  --source /work/camera-hal-mirror
```

커밋 기반 실행은 깨끗한 소스 작업본과 문서의 checkpoint를 사용합니다. 미러링이 force-push로 이력을 바꿔 checkpoint가 조상이 아니게 되면 중단합니다. 새로운 기준을 선택하고 문서를 재검토해야 하므로 자동으로 HEAD를 기준으로 삼지 않습니다.

1. 문서 작업 실패 시 원본과 checkpoint를 유지합니다. 다음 실행은 같은 미처리 구간을 포함합니다.
2. 문서 생성 후 프로젝트가 사용하는 PR·리뷰 절차에 변경 사항을 제출합니다.
3. 검토·반영 후 `ack`로 기준 커밋을 기록하고 checkpoint 변경을 문서 저장소에 커밋합니다.
4. 다음 실행은 기록된 커밋 이후만 이슈와 변경 이력으로 수집합니다.

코드와 문서를 같은 미러 브랜치에 혼합하면 Gerrit 미러링과 문서 커밋이 충돌할 수 있습니다. 사내 예제는 별도 문서 프로젝트를 사용합니다. 현재 HALCamera 앱처럼 미러링이 없는 프로젝트는 같은 저장소의 문서 폴더를 사용할 수 있습니다.
